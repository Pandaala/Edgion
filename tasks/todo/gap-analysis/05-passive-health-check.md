# 05 - Passive Health Check (被动健康检查)

**优先级**: P0 - 生产必备

## 问题

Edgion 有主动健康检查（定期探测），但缺少被动健康检查（基于真实流量的异常检测）。主动检查有探测间隔窗口，被动检查能基于实际请求实时发现后端异常节点。

## 竞品对比

| 网关 | 实现方式 |
|------|---------|
| APISIX | 基于真实流量的成功/失败计数，超过阈值自动摘除节点 |
| Kong | 被动健康检查，通过 TCP 错误和 HTTP 状态码判定 |
| Envoy | Outlier Detection：连续 5xx 错误、成功率、延迟百分位，自动弹出异常节点并定时恢复 |

## 需要实现

- [ ] 基于真实流量的错误统计（连续 5xx 数、错误率）
- [ ] 可配置的摘除阈值（连续错误 N 次、错误率超过 X%）
- [ ] 自动摘除异常节点（从负载均衡池移除）
- [ ] 定时恢复探测（摘除后经过冷却期重新加入）
- [ ] 与现有主动健康检查协同工作
- [ ] Prometheus metrics（摘除次数、当前被摘除节点数）

## 与熔断的区别

- 被动健康检查：针对单个 backend 节点的摘除/恢复
- 熔断 (01)：针对整个 upstream 的流量切断
- 两者互补，不可替代
