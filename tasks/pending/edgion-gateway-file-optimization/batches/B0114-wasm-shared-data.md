## Handoff
- Queued analysis: change, medium severity and high value, complex/plan-first. Delete and recreate currently reuses CAS `1`, allowing a stale token to overwrite the new value; aggregate capacity uses non-atomic load/check/fetch-add across shards, so concurrent writers can permanently exceed the documented 4 MiB hard limit.
- Candidate correction: allocate nonzero monotonically advancing CAS tokens per successful value write and make growth/new-entry reservation atomic, with reserve-before-publish and mutate-before-release ordering. Keep key-level DashMap atomicity, status precedence, counters, and gauge update timing.
- Candidate tests: delete/recreate stale-CAS rejection, zero-skipping wraparound, exact single-slot concurrent reservation, map/accounting coherence, and rejection atomicity. No integration issue is expected.
- Deferred candidate: shared-data gauge generation identity and eviction lifecycle crosses `shared_data.rs`, `vm_manager.rs`, source-label ownership, and metrics inventory; do not implement it in this batch.
- Refresh: confirmed at `05875438` after B0113. Both defects remain in the unchanged `shared_data.rs`; B0113 changed only response-chunk ownership and did not alter shared-data ABI status, generation, or concurrency. The exact implementation boundary remains the one owned file.
- Required semantics: allocate one store-wide opaque nonzero token for every successful value write after CAS validation and capacity reservation, skip zero with a compare-exchange loop, consume no token on ordinary failures or deletes, and accept only unavoidable full-cycle reuse. Reserve new/growing bytes with a checked atomic compare-exchange loop; publish before disarming an unwind-safe reservation guard, while shrink/delete publish removal before releasing bytes. Preserve per-key DashMap serialization, failure precedence, relaxed quota ordering, post-commit gauge timing, and owned guest-copy reads.
- Required tests: delete/recreate stale-CAS rejection, forced wrap without zero or duplicate-next token, no token consumption on ordinary failures/deletes, deterministic barrier-controlled single-slot reservation with rollback, public concurrent hard-cap enforcement, exact post-join map/accounting equality, and rejected mutation atomicity.
- Deferred: D0076 owns aggregate same-label gauge identity across overlapping ModuleEntry generations and final-drop zeroing; it must not add generation labels or alter B0114's existing metric API.
- Implementation plan: keep the public `set` signature and add only private store-wide token allocation, checked total-byte reservation, RAII rollback, and low-limit test seams. The token CAS loop advances from an internal zero state to `1`, issues `u32::MAX`, wraps to `1`, and never publishes zero. Vacant/growing writes reserve globally before allocating a token and publishing; the returned DashMap guard remains held until the non-panicking reservation commit. Shrink/delete publish first and then release their exact charge. Relaxed atomics provide the independent token/quota modification orders while DashMap guards publish values. Ordinary failures and deletes consume no token, and all metric work remains after coherent commit/release.
- Plan safety proof: `total_bytes` equals published entry charges plus live reservations. An uncommitted reservation cannot underflow on rollback because no other key can release its bytes, and the same-key shard guard prevents mutation of the pending publication. No global lock, poison flag, panic catcher, public test API, dependency, or cross-file edit is introduced.
