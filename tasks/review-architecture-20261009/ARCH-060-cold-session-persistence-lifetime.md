# Resolve session persistence lifetime with the publishing rule generation

`SessionPersistence.absolute_timeout` stays as an operator-authored string in the effective HTTP or gRPC rule. `edgion-resources/src/resources/http_route.rs:1591-1635` implements a separate complete GEP-2257 parser in `parse_gep2257_duration_secs`; `SessionPersistence::validate` calls it at admission. Unlike the already resolved route timeout and retry fields, no resolved session-lifetime scalar is published for requests. The actual response path in `edgion-gateway/src/routes/http/proxy_http/pg_upstream_response_filter.rs:359-363` invokes this parser again for every response issuing or refreshing a session token. This is bounded work, not an unbounded input or measured latency incident, but it is repeated interpretation of immutable configuration and a second owner of the duration grammar.

The call is reachable in ordinary production. `sp_apply_extracted_token` sets `InjectNew` when no token exists or a token expires; fallback selection can request `InjectUpdate`. After retry-on-status decisions, the shared HTTP response callback handles those states for both HTTPRoute and GRPCRoute. `EdgionHttpContext::effective_session_persistence` borrows the configuration from the captured HTTP or gRPC rule unit; it has no resolved lifetime to return. The parsed seconds feed both `build_wire_token`, which adds the issuance epoch, and Permanent-cookie `Max-Age`. Session-cookie and Header modes also use the token's embedded expiry. None of these consumers requires parsing the configured text during the response.

The existing cold owner is concrete: `ResourceMeta::pre_parse` chains HTTPRoute path/annotation, timeout and retry preparation, and does the analogous work for GRPCRoute. Gateway full-list and ordinary watch decoding invoke it before caching and compiling immutable rules. Both authored and Controller-flattened rules are prepared, and delegation already selects child-first-otherwise-inherited session configuration. `duration::parse_duration` owns the shared digit, segment and unit grammar. The original unification registry explicitly requires string durations to use that parser, and the graded design index identifies it as canon. A new grammar change currently requires coordinated maintenance of this helper and the canonical parser while also retaining request-time conversion.

Resolve an optional lifetime in seconds once alongside the actual effective rule's session configuration at this existing cold preparation/publication boundary. Use the canonical duration parser for syntax and duration accumulation, keeping the session policy's conversion local: round up sub-second values and retain the current minimum of one second, including the currently accepted zero-duration forms. Preserve strict rejection of surrounding whitespace: the canonical parser deliberately trims input, whereas this field's current helper and structural CRD grammar do not. A small explicit strict-input check before the shared parser preserves that boundary without duplicating digit/unit parsing. The admitted domain has at most four five-digit components; its current maximum safely fits the duration and second scalar. Keep scalar conversion fallible rather than adding truncating casts or relaxing overflow behavior.

Carry the resolved scalar through the same immutable HTTP/GRPC effective generation that supplies the configuration, including delegated rules and the existing HTTP-before-gRPC field precedence. Requests should read that scalar and compute only issuance-dependent expiry. Any in-process preparation cache must remain schema-hidden and excluded from conf_sync serialization, then be rebuilt on Gateway decoding; do not trust an operator-supplied resolved value. An invalid configured lifetime must retain the existing invalid-rule admission outcome, not become the same executable state as an omitted lifetime. A direct compilation boundary must not publish an unprepared lifetime or silently fall back to parsing in the request path. This requires no global cache, policy resource, general context facade, or broader factory rewrite.

An alternative is to replace only the hand-written grammar with a canonical-parser wrapper while leaving request-time conversion. That removes grammar duplication but leaves configuration work in every issuance response. Merely borrowing the configured lifetime avoids an unrelated copy while retaining this cause. The bounded cold projection addresses both the missing runtime representation and its repeated parse without changing session semantics.

Preserve missing-lifetime tokens, ceil/minimum behavior, Permanent-cookie validation, the same lifetime for token expiry and Max-Age, saturating issuance-epoch addition, expiry-at-equality, malformed-token refresh, strict resolved-target versus map-miss behavior, and two-state delegation inheritance. Keep injection after discarded-retry decisions, exclude informational/upgrade responses as today, and retain the accepted loss of the sticky cookie on a replaced local response. No request observability, body storage, TLS, quota or failure-policy changes are needed.

Future verification should cover strict grammar and whitespace, empty/invalid input, zero/sub-second/maximum-domain/compound durations, absent lifetime, both HTTP and gRPC authored/resolved rules, inherited versus overridden session configuration, full/watch publication, and old captured requests across a lifetime update. Actual token and cookie/header behavior should consume one resolved scalar; do not preserve hot parsing for mock convenience. The relevant existing duration, schema, preparse, token-expiry and cookie tests were read but not executed. No runtime reproduction, benchmark, build or implementation was performed. Existing architecture findings were searched by this cause; no session-lifetime projection finding was found.
