# Mutate only the canonical RegionRouteOverride table during failover

edgion-controller/src/api/region_route_handlers.rs::patch_failover_resource first searches /spec/plugins for matching type and region. Only when that search finds no matching region does it visit /spec/data. The sole production caller passes RegionRouteOverride, then validates only /spec/data/config/regions in validate_failover_resource before returning success or persisting the proposed raw document. Mutation and validation therefore address different possible tables.

Current EdgionConfigDataSpec carries exactly one data: ConfigEntry. Its deserialize-only shadow ignores unrecognized spec keys; strict ingest captures unknown paths rather than rejecting the RegionRouteOverride variant. EdgionConfigDataHandler::preparse records advisory unknown-field diagnostics and continues this variant. The CRD likewise declares spec.data and no spec.plugins; Kubernetes normally prunes the latter. The obsolete plugins branch is outside the current typed contract, rather than a supported second table owner.

The actual FileSystem path preserves this distinction. AdminState::center_get_resource reads get_one and parses the stored document into an untyped Value. FileSystemStorage::get_one returns the raw file; update_one_if_version checks the current version and merge_operator_update_yaml preserves the requested spec while merging identity, metadata and status. A hand-authored file can therefore retain an unrecognized spec.plugins alongside a valid canonical RegionRouteOverride in spec.data.

A concrete source-level witness starts with valid canonical east and west regions, no east failover, and a legacy spec.plugins entry of type RegionRouteOverride containing east. Requesting east -> west changes the legacy entry, sets matched=true and skips spec.data. The complete canonical table still validates, so the helper persists the legacy mutation, advances the local resourceVersion and reports success/modified=true. The Gateway's EffectiveRegions and compute_effective_regions consume only resource.spec.data, as does the Controller effective view. The effective east routing remains unchanged. If the ignored legacy entry already names west, AlreadyApplied similarly reports success without establishing that state in the canonical table. This is a supported raw FileSystem ingestion witness, not a claim that normal typed Admin creation retains unknown fields, that Kubernetes preserves them, or that an executed outage occurred.

Remove the legacy /spec/plugins search from this private helper and select only the exact RegionRouteOverride data entry whose regions the existing validator checks. Reuse patch_region_failover and existing typed complete-table validation. Reject an absent/wrong-type canonical entry through the current Missing path. Preserve unrelated raw fields rather than round-tripping the entire object through the typed resource or imposing a new global unknown-field rejection policy. No compatibility adapter, schema expansion, second mutation owner or generic patch framework is needed. The project explicitly has no pre-release compatibility burden.

The maintenance gain is one current schema owner for the dedicated command's read, mutation and validation. Keeping both paths permits a schema migration remnant to take precedence over live state. Merely validating both tables would add another policy for an unsupported shape and still leave routing unchanged. Removing the endpoint is not proposed: the original controller-region-route-endpoints-retained-for-drill-in decision establishes its live effective-view/failover purpose and synthetic authorization contract.

Preserve per-key serialization against generic updates, backend conditional writes, three conflict attempts, fresh non-Kubernetes resourceVersion, server-assigned Kubernetes versions, whole-table validation even for idempotent requests, 422-before-write for invalid candidates, missing-region behavior, clearing failoverTo, existing readiness/authn/authz and the one-resource mutation limit. Preserve whole-table overlay replacement, per-consumer modulo checks, one-hop routing, fail-to-base, source authorization and unchanged body/logging ownership. The concurrency and effective-table regression guards protect these actual contracts; neither requires the legacy plugins branch. Existing review artifacts and pending tasks were searched by helper and shape and no matching finding was located.

The complete actual region_route_handlers_test.rs and failover_version_tests.rs bodies were read. They cover strict command fields, field-local patches, canonical resourceVersion advancement, invalid self/dangling/cycle targets and invalid complete tables; none supplies both competing shapes. Future verification should drive the actual FileSystem helper with such a mixed raw document and assert canonical failover changes, clearing and idempotence; ignored legacy data remains unchanged. Include invalid canonical target/table controls asserting 422 and unchanged stored version/data, and wrong-type/missing canonical controls. Preserve existing effective-view and conditional-write checks. No builds, tests, application or network operation was executed.
