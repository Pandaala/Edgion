# Read complete fixed echoes before judging L4 connection health

L4TimeoutHotReload treats one stream read as one complete echo message. A correct TCP or TLS-terminated relay can return the authored payload in several reads, causing this scenario to report an echo mismatch before it tests timeout publication or retained-connection health. The defect is confined to the test-owned fixed-message reader, not the Gateway relay or its idle policy.

In edgion-tests/src/client/dynamic/scenarios/l4_timeout_hot_reload.rs:202–220, echo writes the 15-byte TCP_ECHO with write_all, reads once into a 64-byte buffer under IO_TIMEOUT, and requires that returned slice to equal the entire payload. Both PathKind::Tcp and PathKind::Terminate use this branch. The authored TCPRoute and TLSRoute terminate fixtures select the shared test-tcp backend on port 30010. test_server.rs::start_tcp_server:4158–4185 repeatedly reads arbitrary chunks and writes each received chunk back. Gateway l4_duplex.rs::RelayDirection::poll_step likewise forwards available bytes and preserves partial-write cursors; the TCP and TLS terminate proxy duplex callers use this canonical relay. None of these producers supplies an application-message boundary to one client read.

A concrete legal exchange is the expected payload arriving as the five bytes `l4-ti` followed by the remaining ten bytes `meout-echo`. The server and relay can deliver those bytes in order without an error. If the first client read completes with five bytes, the current equality assertion fails even when the remaining bytes are already pending or arrive before the three-second IO_TIMEOUT. No actual flake rate or executed incident is claimed. This is a source-level false-negative witness under valid stream segmentation.

The supporting ESP allow-echo case has the same framing defect. edgion-tests/src/client/suites/tcp_route/stream_plugins/esp_reload.rs::test_allow_echo writes the 15-byte Hello EspReload, performs one three-second read into a 1024-byte buffer, and rejects a proper prefix as an echo mismatch. TcpEspReload invokes that allow suite in its initial and restored phases. Its authored TCPRoute selects test-tcp-sp-reload, whose EndpointSlice targets the same port-30010 echo server. The full allow helper and scenario were read; this is supporting evidence with zero primary coverage. It does not incorporate that helper's separate deny-error classification or the scenario's all-outcome restoration issue.

The affected helper is used by the ready phase, the disposable TCP publication probe, each pre-update connection setup, each post-update connection setup, and the final exchange on the retained connections. Initial readiness/publication polling may retry an isolated mismatch; the captured transition's setup and final retained-connection exchanges propagate it directly. Correct timeout publication can therefore fail the scenario independently of its intended old-versus-new generation assertions. The passthrough HTTP response reader is a different framing owner and is outside this recommendation.

Read exactly TCP_ECHO.len() bytes into a private fixed-size buffer and then compare the complete buffer with TCP_ECHO. Wrap the entire read_exact future in the existing IO_TIMEOUT; do not restart a timeout for each fragment. Preserve the bounded write operation, byte equality, failure on premature EOF or read errors, and operation-specific error context. Apply the same fixed-message read ownership to the supporting ESP allow helper, using its authored payload length and one existing three-second read budget. Preserve its connect and write behavior, exact equality, case identity, fixed listener and phase wiring; a read failure returns a failed case and drops that local stream. The existing edgion-tests/src/client/suites/plugin_policy/mod.rs::tcp_probe uses a fixed payload-size buffer and timeout-wrapped read_exact for a real TCP echo, so this needs no shared framing framework, public production seam, new dependency or server change.

Preserve the scenario's generation test: publish the long idle timeout, complete exchanges before capturing retained connections, update only the EGC to the short timeout, prove live TCP publication, require fresh connections to close inside SHORT_IDLE_MIN/SHORT_IDLE_MAX, and verify old connections remain usable after OLD_CONN_IDLE. Keep TLS handshake/setup limits, the HTTP passthrough branch, supported terminate capability deferral, restoration of the long timeout after either outcome, and restoration-error propagation. A failed or timed-out exact read ends the current probe/transition; do not retry an echo on the same partially consumed stream. read_exact cancellation does not promise that a partially consumed connection can be reused. The existing control flow already returns the error and drops that probe's connection or exits the captured transition before restoration.

The original L4 timeout publication guard explicitly requires completed backend exchanges and distinguishes relay timeout generation from listener/handshake lifecycle. The integration testing guide requires actual response assertions and bounded convergence, and the lifecycle guard requires assertion errors to affect outcomes. These decisions do not authorize a packet-boundary assumption. Accepted fixed topology and connect-timeout coverage limits remain unchanged. No production logging, access logs, metrics, TLS backend, request/response body storage, egress policy or Controller workqueue changes are requested.

Future focused verification should drive the existing fixed-echo reader with several legal fragment sequences, including a prefix followed by the rest within one operation budget, and retain mismatch, premature EOF and pending-read timeout failures. A network-free asynchronous stream fixture is sufficient for framing; it must not replace the scenario's real TCP/TLS, new-connection idle-close and retained-connection assertions. Confirm that timeout aborts the probe without attempting same-stream reuse and that the captured result still reaches bounded restoration. Retain TcpEspReload's initial, deny and restored phase identities without claiming this framing correction closes its separate denial-evidence or restoration gaps. The primary scenario, supporting ESP phase implementation, authored routes and endpoint, actual server/relay callers, actual relay unit bodies, the existing exact-read precedent and original decisions were independently read. No tests, build, network operation, external source or repository mutation occurred.
