# ARCH-345 — Configure the response-body probe required by the Kubernetes BodyPlugins suite

The repository-owned Kubernetes BodyPlugins fixture runs the reference Wasm guest without the response-body probe configuration, while the selected suite unconditionally requires the counter emitted by that probe to increase. A successful nonempty response can therefore fail the test even when the production response-body callback behaves correctly. This is a test-fixture behavior defect, not evidence of a production Wasm defect or an observed integration incident.

The primary owner is edgion-tests/src/client/suites/edgion_plugins/body_plugins.rs. wasm_response_body_hook at 1631–1709 warms the wasm-body.example.com route, scrapes edgion_wasm_body_pause_unsupported_total, requests /headers again, requires HTTP 200 and a nonempty complete response, and passes only if the second scrape is greater than the first. test_cases at 1717–1751 includes this case without a Kubernetes exclusion. test_client.rs:3066–3072 installs BodyPluginsTestSuite for the literal selection, and run_k8s_integration.sh:2549 selects EdgionPlugins/BodyPlugins in the static sweep. The runner's current default conf root and apply branch use the Kubernetes fixture tree, followed by the existing common test-client batch invocation.

The deciding mismatch is in k8s/conf/EdgionPlugins/BodyPlugins/resources.yaml:129–136. The wasm-body upstreamResponseBodyFilterPlugins entry loads /usr/local/edgion/test-assets/header_demo.wasm but omits pluginConfig. The corresponding local fixture, integration/conf/EdgionPlugins/BodyPlugins/14_EdgionPlugins_wasm-body.yaml:24–33, supplies pluginConfig.string: response-body-probe. The Kubernetes resource already includes the correct route at 654–664, host, ExtensionRef and test-http backend; this is not missing registration or a missing route.

The configuration distinction changes the actual callback result. vm_manager.rs decodes an absent pluginConfig as an empty byte vector and passes those bytes to the guest's configure hook. host_abi.rs exposes that vector as PluginConfiguration. In the real reference guest, header-demo/src/lib.rs:111–118 enables response_body_probe only when the configuration equals response-body-probe, and 145–149 copies that flag into each HTTP context. Its response-body callback at 250–259 returns Pause for a nonempty chunk only when the flag is enabled; otherwise it returns Continue. The current production Wasm response callback, plugin.rs:568–592, records the existing unsupported-Pause counter only for a nonzero action. Continue does not increment it. Reading a nonempty response cannot substitute for enabling this guest mode.

The artifact path is also real: deploy_integration.sh:151–155 creates the test Wasm ConfigMap from edgion-tests/wasm/artifacts/header_demo.wasm, and the Gateway deployment mounts that ConfigMap key at the configured path. wasm/build.sh and wasm/README.md identify this checked-in artifact as the build output of the reference guest. The README expressly documents the response-body-probe configuration and counter-delta assertion. In a quiet default Kubernetes topology using that authored guest, the requests in this case cannot produce the expected Pause-counter delta. Unrelated traffic or externally supplied resources could mask the mismatch because the assertion sums matching metric series; this finding does not claim an isolated counter or an unconditional failure under every environment.

The bounded improvement is to supply pluginConfig.string: response-body-probe on this Kubernetes response-stage Wasm entry through the existing fixture publication path. Keep the request-stage guest configuration unchanged: it serves the independent whole-request-body counter and mutation cases. Preserve the current host, route, namespace, artifact mount, timeout, fail-closed setting and backend. Add a small fixture-contract check for this specific response-stage mode if useful; no runtime registry, new fixture framework, production metric or logging change is required.

A narrowly documented Kubernetes exception would be an alternative only if the supported topology could not exercise the callback contract. The existing mounted guest, route, backend and metric endpoint already provide the needed mechanisms. Skipping the case, accepting an unchanged counter, or removing its nonempty-response assertion would discard meaningful supported coverage. Changing the host to increment the counter for Continue, enabling response accumulation or implementing Pause buffering would alter production semantics to conceal a fixture defect.

The body-suite-sweep-registration decision preserves BodyPlugins in supported sweeps. The Wasm counter-delta regression guard requires rerun-safe observations rather than resets or fresh Gateway processes. The read-only body-filter decision preserves current-chunk response observation and ordinary streaming; its historical whole-body scaffolding discussion does not authorize response aggregation. The existing body_pause_is_metered_and_never_breaks_the_stream unit test uses a real Pause guest and checks that the callback returns no throttle or interruption; its current assertions do not independently check the exported counter value. No retrieved original decision accepts omitting the probe mode from a selected Kubernetes case.

This cause is distinct from ARCH344, which supplies absent retry-quota route/plugin resources to another already selected suite, and ARCH304, which owns missing dynamic execution registration. ARCH264/265 restoration and cleanup, ARCH266 selected Controller status and ARCH296 resolved listener consumption cannot enable this guest's response mode. Current artifact and owning-knowledge searches found no existing report for this mode mismatch.

Future verification should retain the complete BodyPlugins case set, inspect the published response-stage configuration, run the selected local and Kubernetes suites, and rerun against the same Gateway process. Require nonempty HTTP 200 responses and a positive before/after counter delta while request-body byte/call/EOS assertions, mutation/retry/mirror behavior and negative cases remain intact. Preserve request-only canonical BodyStorage, physical caps, per-chunk streamed responses, cancellation and existing access-log/metric ownership. This read-only review ran no build, test, checker, network call or artifact execution, and makes no claim that repairing this field guarantees every other Kubernetes case passes.
