# Make positive cipher probes assert completed, fixture-permitted negotiation

The four positive cipher cases in `edgion-tests/src/client/suites/edgion_tls/cipher/cipher.rs` use a weaker acceptance predicate than the same suite's three policy/fail-closed cases. `get_tls_info` and `test_with_specific_cipher` accept `CONNECTED` with any nonempty cipher other than `(NONE)` (84-133). The existing `handshake_truly_completed` rejects the `0000` placeholder explicitly (139-145), but the first four cases bypass that predicate. The two generic legacy/modern cases also return success in both branches of their cipher classification (157-241). The constrained cases accept the helper boolean without requiring the returned cipher to match their single requested cipher (249-309).

A parsed failed-handshake result containing `CONNECTED` and `Cipher: 0000` therefore satisfies each weak positive helper, despite being rejected by the suite's existing completed-handshake predicate. A completed negotiation with a cipher outside the fixture's configured set also passes both generic cases. These are individual assertion gaps; the remaining negative and shared-SNI cases have their own stronger predicates and may still reject a broken deployment. No whole-suite false pass, live incident or production TLS-policy failure is claimed.

Local and Kubernetes cipher fixtures configure four exact legacy ciphers and four exact modern ciphers. The current `LEGACY_CIPHERS` list includes only three of the four legacy names; `MODERN_CIPHERS` lists two of the four modern names, excluding the configured ECDSA choices. Those constants are incomplete inventories, although the current broad SHA/GCM display checks also admit the remaining configured names. Tightening acceptance by treating the constants alone as exact allowlists would omit the fourth legacy cipher and both configured ECDSA modern ciphers. The acceptance owner must encode the complete actual configured set rather than preserve broad substring matching or rely only on those incomplete constants. This does not claim that an ECDSA cipher currently negotiates with the RSA-backed fixture. Both fixture families bind the intended three listener ports and per-SNI TLS versions.

Use one private parsed-result acceptance path for positive probes, reusing the existing strict completion predicate and explicitly requiring TLS 1.2 plus the exact fixture-permitted cipher. For the two constrained probes require the exact requested cipher as well. Preserve all seven case identities/order, resolved target ports, SNI values, OpenSSL invocation errors/timeouts, negative policy assertions and shared-port behavior. This needs no production cipher change, shared framework, additional metrics or runtime registry. An alternative is narrowly enforcing each case locally, but keeping parallel weak and strong definitions would retain the demonstrated acceptance drift.

The production `apply_edgion_tls_cert` processes operator cipher configuration before certificate/key binding, and `configure_ciphers` rejects an unsuccessful strict BoringSSL call. The actual unit test `uncompilable_operator_cipher_fails_closed_before_binding_identity` covers invalid compiled operator cipher material before identity binding; it does not replace these network negotiation assertions. The historical cipher fail-closed knowledge is scoped evidence of that production ordering, not proof that every current positive test discriminates its expected policy.

Future verification should exercise the pure private acceptance decision with empty, `(NONE)` and `0000` ciphers, missing/wrong protocol, a completed wrong-policy cipher, every exact permitted fixture cipher, and constrained requested/negotiated mismatch. Retain the existing live seven-case suite for wiring. The existing subprocess runner already has a ten-second `try_wait` watchdog with kill/wait; this finding is distinct from ARCH-288's unbounded child-operation ownership. No production hot-path allocation, response-body aggregation, observability, secret, workqueue or supported-backend policy change is proposed.
