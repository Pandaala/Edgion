# Retire the orphan file-based LB verification surface

`AccessLogAnalyzer` is exported from `edgion-tests/src/lib.rs`, but the current repository has no non-test caller of its constructor, `analyze_by_prefix`, `generate_report`, or `LBAnalysisResult`. All uses are in the analyzer's own unit tests. The registered RoundRobin suite instead sends successful sequential traffic and asserts exact request, endpoint and Service counter deltas through the existing metrics APIs. Live retry/log assertions use `AccessLogClient` against the Gateway's integration-only access-log store. Keeping this exported analyzer maintains an additional verification contract that is detached from both active paths.

The primary implementation owns a second request/upstream JSON model, file parsing, readable trace-prefix selection, policy classification and success reporting (`log_analyzer.rs:12-46,68-139,143-205`). Its tests deliberately preserve permissive contracts: malformed nonblank lines are ignored without contributing an analysis error; missing or non-string/non-object policy values become RoundRobin; the last upstream wins; and readable fixture IDs such as `rr-test-0001` are selected by string prefix. `generate_report` marks an analysis as verified whenever `errors` is empty, including an analysis with zero matched requests. These are concrete maintenance obligations of the retained API. They are not evidence that any current integration suite passes incorrectly, because those suites do not call this API.

The active marker producer has changed the useful selection boundary. `traceparent_for_marker` hashes readable markers into stable nonzero W3C trace IDs, and `AccessLogClient` normalizes those same markers for lookup (`access_log_client.rs:16-39,339-380`). The real RoundRobin request producer uses that helper, so a readable prefix such as `rr-eps` does not select its generated log IDs. A future author choosing this public analyzer for a new LB test would need a new identity-selection contract and meaningful count/outcome assertions, then maintain another owner for assumptions already addressed by the active suite. The current JSON policy parser still recognizes the presently serialized LB enum shapes; this proposal does not claim a live format incompatibility.

The actual registered owner is `LBRoundRobinTestSuite`: `test_client.rs:1859-1863,1940-1945` registers it, and `lb_roundrobin.rs` derives the expected fixture endpoint set, validates successful status/body completion, takes counter snapshots, and requires exact per-endpoint and Service deltas. Its unit tests reject missing, unbalanced, unexpected, wrong-Service and unattributed traffic. `retry_on_status.rs:19-90` independently checks the live canonical upstream retry reason through `AccessLogClient`. Original integration guidance prefers existing metrics for LB behavior and access logs for request/plugin facts; the scoped-delta guard requires generated requests and their actual deltas to determine the verdict. The analyzer's self-tests do not provide those live guarantees.

Retire the unused analyzer module and its single `pub mod log_analyzer` export after repeating the complete caller search against the implementation baseline. Retire only tests whose subject disappears with that module. Do not redirect or simplify live suite assertions, remove integration fixtures, change canonical Gateway log serialization, alter the trace-ID helper or AccessLogStore semantics, or broaden this work into MetricsClient cleanup. The improvement is one fewer independently maintained verification surface and a clearer choice of the existing assertion owners; it makes no throughput, allocation or current false-pass claim.

Preserve the live identities `roundrobin_eps`, `roundrobin_multi_slice`, `retry_502_then_200`, and every other existing integration case, together with their registration/listener keys, fixture paths and assertion behavior. Preserve the RoundRobin unit identities `exact_counter_delta_passes`, `missing_unbalanced_and_unexpected_traffic_fail`, `wrong_service_and_unattributed_metric_fail`, `endpoint_resolution_is_topology_aware_and_fail_closed`, and `integration_gateway_configs_enable_backend_identity_metrics`. Preserve the marker test `markers_preserve_repeated_lookup_and_valid_w3c_identity`. These bodies inspect meaningful behavior belonging to the active owners. The analyzer's private parsing/counting tests exercise only the proposed retired API; no claim is made that they are interchangeable with every aspect of a live metrics or log test.

A reasonable alternative is to retain this as a deliberately supported offline diagnostic tool. That would need a named executable or actual repository caller, a documented identity input contract, and explicit differentiation of no evidence, incomplete parsing and verified policy. No such consumer or documented tool contract was found. Introducing one solely to justify the existing helper would enlarge scope; if a separately authorized consumer appears, re-evaluate retirement instead.

Future verification should repeat the whole-repository symbol/export and documentation search, compare all retained integration test identities/fixtures/listener registrations before and after the bounded removal, and run the relevant harness checks only when implementation is authorized. Original root rules permit scoped pre-release retirement without compatibility shims; they do not authorize mutation during this review. This is a P3 structural recommendation, not a runtime defect or a security incident.
