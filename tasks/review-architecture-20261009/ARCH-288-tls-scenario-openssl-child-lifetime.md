# Bound OpenSSL child lifetimes in the existing TLS scenario helpers

## Current ownership and evidence

The scenario owns serial convergence, valid certificate A -> invalid update -> A recovery -> valid certificate B -> invalid update -> A restoration. Its generation producer, generate_rotated_secret at edgion-tests/src/client/dynamic/scenarios/edgion_tls_last_known_good.rs:63-105, invokes std::process::Command::output synchronously inside run's asynchronous execution at line 145. The same run synchronously calls stash_fixture_serial before its captured transition result at lines 130-132, after generation at 146-148, and inside restoration at 160-162.

The actual phase suite in suites/edgion_tls/last_known_good/last_known_good.rs reaches get_served_serial at 57-86 from asynchronous cases at 239-271 and 319-363. This helper synchronously waits for openssl s_client with stdin closed and no operation deadline, then calls get_pem_serial at 88-117, which synchronously writes child stdin and waits for openssl x509. stash_fixture_serial at 208-229 also reaches that parser process. These are live callees, not unused utility functions.

Three additional registered suites have the same operation-owner defect. suites/edgion_tls/sni_collision/sni_collision.rs synchronously probes candidate binaries with version at 36-44 and waits for s_client.output() at 68-87 inside its async oldest-wins case. suites/edgion_tls/fallback_sni/fallback_sni.rs synchronously probes s_client --help at 36-63 and waits for s_client.output() at 74-92 from both async SNI cases. suites/edgion_tls/wildcard_single_label/wildcard_single_label.rs waits for s_client.output() at 60-69 from all three async single-label, deep-label and apex cases. Their CLI targeted and aggregate registrations are live. Binary capability discovery is also a child operation; closing stdin does not establish a handshake or process-completion deadline.

TestCase::new supplies a 30-second timeout, and TestCase::run wraps the case future in tokio::time::timeout at framework.rs:545-576. ScenarioCtx::wait_phase checks its own 15-second phase budget only after assert_phase returns. Synchronous process waiting inside a future poll does not yield control to either timeout. A child or a TCP peer holding TLS negotiation can therefore delay these cases' timeout decisions until the blocking operation returns. In the last-known-good scenario, a blocked transition probe also delays reaching the existing captured-result restoration path.

This is a source-supported failure scenario, not a reproduced outage or a claim about every failed handshake. The outer run_all_integration.sh job boundary uses the canonical run_with_deadline.py process-group wrapper. It remains valid independent containment and is not removed or called ineffective. The direct registered scenario and targeted static entries also exist, and run_integration.sh's ordinary run_test executes test_client without adding an operation-level OpenSSL watchdog.

Cipher is a concrete counterexample to a blanket claim about all TLS probes. suites/edgion_tls/cipher/cipher.rs:47-80 already polls its spawned child with try_wait, enforces a ten-second deadline, and attempts kill followed by wait. This finding does not classify that helper as an unbounded output() site or automatically extend its implementation scope; the existing synchronous watchdog has a different shape and remains separate.

## Bounded improvement

Keep OpenSSL invocation and serial extraction in these existing test-owned producers/helpers, but make their callers asynchronous and give each child operation an explicit bounded lifetime. Use the already available native asynchronous process support, await a finite operation deadline, and own child termination and reaping on timeout or cancellation. Bound the entire operation, including piped input, output collection and process completion. A timed-out handshake must become an ordinary failed assertion, not evidence that an expected negative SNI handshake was correctly rejected. After last-known-good transition processing begins, the existing captured-result flow must remain able to proceed to restoration; restoration's own OpenSSL operations need the same boundary. Initial fixture-serial seeding precedes that captured block and must still fail before applying a transition when it cannot establish the baseline.

Propagate the async seam through get_pem_serial, get_served_serial, stash_fixture_serial, generate_rotated_secret and their actual callers, plus the three supplemental suites' existing child-based discovery and handshake helpers. Keep discovery candidate order, capability criteria, output parsing and actual case identities intact. Reuse native asynchronous process support; no existing generic bounded child owner was found in these test call chains. Preserve cleanup on both transition outcomes. No new scheduler, second topology, generalized subprocess framework, product runtime change or dependency is needed. Exact native child API and cancellation/reaping behavior must be reviewed during implementation; merely changing Command's namespace or wrapping output in timeout without owning child cleanup is insufficient.

An alternative is eliminating local x509 subprocesses using an already supported certificate parser, while retaining a bounded owned handshake and certificate-generation child. That changes the serial-format seam and needs explicit equivalence verification. Moving the current synchronous calls to spawn_blocking alone is not a complete remedy: dropping a timeout's future does not stop that blocking operation or its external child.

## Original decisions, value and limits

The original testing deadline guard distinguishes per-case readiness from complete job containment and requires the canonical outer watchdog. This proposal preserves that watchdog and supplies the missing operation owner inside a nominally timed async case. The lifecycle rule requires failures to affect outcomes; the current scenario's result/restoration match is already useful and should remain. The accepted EdgionTls resource-key last-known-good rule remains unchanged, including its distinction from UID-bound retention. The primary's comments correctly limit live availability/status evidence versus Gateway-store unit coverage.

The structural value is making child lifetime part of the existing scenario/helper boundary so timeout and cleanup decisions remain executable. There is no throughput, allocator, precise whole-scenario wall-clock or process-wide interruption guarantee. A deadline cannot promise prompt progress under an indefinitely stalled OS scheduler or uninterruptible process state. These supplemental sites share this existing OpenSSL child-lifetime root cause rather than creating separate findings. ARCH264 concerns scenario state restoration, whereas the last-known-good scenario already has restoration whose progress is blocked by synchronous child waits. ARCH272 concerns aggregate TLS child context and does not replace child lifetime ownership. Static read-only evidence only; no incident, external oracle, benchmark or dependency implementation claim is made.
