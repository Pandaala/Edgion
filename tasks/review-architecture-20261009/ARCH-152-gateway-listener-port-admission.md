# Reject unrepresentable Gateway listener ports before deriving socket identity

GatewayHandler::validate at gateway.rs:482–599 bounds listener count and frontend.perPort ports but does not validate the ordinary spec.listeners[].port. Listener.port is an i32 at edgion-resources/src/resources/gateway.rs:158–160; its schemars range annotation does not enforce serde decoding. The existing canonical gwapi_types::is_valid_port already owns the inclusive 1..=65535 predicate and explicitly documents FS-mode validation consumers.

A canonical Gateway/v1 filesystem or etcd document with one ordinary HTTP listener on port65537 provides a concrete witness. parse_resource_content_offline accepts the supported source identity and deserializes that i32. Its source-schema branch is limited to selected non-v1 Route/policy adapters, so Gateway v1 and its v1beta1 adapter do not receive a full OpenAPI pass. Both real static-backend controllers insert the parsed object and invoke the serial processor. ResourceProcessor calls handler.validate, then continues into parse and update_status. With otherwise valid input and no reference/conflict error, this Gateway and listener report Accepted=True and Programmed=True.

parse creates the listener registration at725–745 using resolve_listener_addr, whose address conversion is listener_port as u16. Thus65537 becomes physical port1. The supported Gateway startup path does not repair it: configure_listeners prepares PROXY policy from the same cast, builds the listener key/socket address, and dispatches the HTTP builder, which repeats the cast before bind probing and service registration. Port0 is also admitted and means a dynamic socket allocation rather than a stable Gateway API PortNumber. No successful privileged bind, reachable traffic, production incident or API-server bypass is claimed; the deterministic defect is accepting and publishing an invalid port with a different physical identity.

Use the existing canonical is_valid_port predicate in a small handler-owned listener-port gate. Report a stable source-indexed validation error, and apply the same gate before any PROXY contribution, ListenerPortManager registration or serving projection uses the port. The existing invalid-Gateway listener-withdrawal path is a bounded implementation option: retain the identifiable object for Accepted=False/status, clear the prior listener projection and replace its registrations with empty contributions rather than publishing a truncated port or preserving the previous listener generation. A range error logged only by validate is insufficient because processing deliberately continues. Do not clamp, modulo, silently default, reinterpret port0, or add a complete watcher OpenAPI validator.

Preserve valid1 and65535, source-version adapters, canonical local-bind-IP handling, class ownership, dependency cleanup, PROXY policy conflict/requeue ordering, publication proofs and route refresh. Preserve the accepted frozen-socket/restart contract: clearing invalid routing projections does not unbind an existing socket, and this finding authorizes no dynamic listener implementation. Keep one serial worker/queue, asynchronous direct-write status feedback, inline ordered status IO, typed secret/redaction boundaries, BoringSSL-only support and existing logs/metrics. A checked conversion in every downstream builder is a defensive alternative, but by itself leaves Controller success status and derived identity incorrect; the source-owned gate is necessary. Any independently scoped data-plane defensive guard must use the same canonical predicate rather than another port grammar.

Actual tests gateway_address_without_value_is_status_rejected_and_recovers and oversized_raw_listener_vector_is_revoked_before_traversal establish the handler's existing invalid-generation withdrawal/recovery pattern. frontend_runtime_validation_rejects_duplicate_range_and_nonempty_group covers the distinct perPort field. The real route_refresh_tests exercise post-publication refresh and invalid/corrected Gateway updates; their bodies were read. They do not test ordinary invalid listener ports. Future verification should drive real offline parsing and ResourceProcessor processing for v1/v1beta1, ports-1,0,65536,65537 and i32 extremes, with valid1/65535 controls. Assert no invalid port contributes a physical listener identity, an existing valid generation's derived registrations are replaced, status is invalid and a corrected generation recovers through the existing queue. No test or application was run.

This proposal preserves that accepted architecture. The original startup-only listener decision separately declines runtime bind/drain support and remains unchanged. Existing findings and pending reference-contract work were searched; this cause is separate from namespace-selector cardinality, source-adapter parsing, frontend validator duplication and malformed etcd ingress.
