# Reject malformed AllEndpointStatus method overrides before publication

AllEndpointStatusConfig owns the operator-facing optional methodOverride string at edgion-resources/src/resources/edgion_plugins/plugin_configs/all_endpoint_status.rs:73. Its get_validation_error at :116-136 checks zero limits and pathOverride shape but never validates the method; PluginValidation at :160-163 delegates to that function. EdgionPlugin::validation_error at edgion_plugin.rs:773 routes this exact config into the shared enabled-entry validation path. Controller preparse calls validate_plugins_before_waf_resolution at handlers/edgion_plugins.rs:225, and Gateway plugin_runtime.rs:1264-1273 rejects only reported config errors before construction.

Gateway AllEndpointStatus::new at plugins/http/all_endpoint_status/plugin.rs:437-442 clones the unresolved string into its immutable runtime. fan_out_requests at :502 selects the configured string or inherited request method, then at :520 copies it into each endpoint future. At :542 method.parse().unwrap_or(reqwest::Method::GET) silently recovers any parsing error as GET. The production factory at plugin_runtime.rs:2317 constructs this owner without another method check.

An otherwise valid enabled request-stage entry containing methodOverride: "BAD METHOD" therefore passes these configuration gates. When an eligible HTTP route and safe ready endpoints are available, every successfully prepared probe uses GET rather than rejecting the authored method. Empty strings or whitespace-containing method values have the same result. This is a static call-chain witness, not a reported incident or an executed network experiment. The issue is malformed input becoming a different accepted operation; no existing valid method or bodyless-probe policy is claimed defective.

Validate each present override with the existing http::Method parser in stateless Resources PluginValidation. Preserve its full HTTP token language and case: allow valid extension methods and lowercase tokens; do not trim malformed whitespace, normalize case or restrict to a fixed standard-method list. Resources already depends on http, the lockfile resolves http 1.5.0, and reqwest 0.12.28 re-exports this same Method type. Its current source rejects empty input and invalid token bytes while retaining extension spelling.

Prepare an optional parsed Method once when constructing the immutable AllEndpointStatus runtime. Make preparation fallible even for direct construction, and map failure through the existing construction-declined path, which records an invalid entry and seals fail-closed (plugin_runtime.rs:1570-1581). Keep the operator String serialized in Resources rather than adding a serialized cache. With no override, obtain or parse the inherited canonical request method once before creating endpoint futures; malformed inherited input must return the existing bounded local failure rather than manufacture GET. Each endpoint receives the selected Method without reparsing the immutable config. This requires only this schema, runtime owner and narrow factory/call-site updates; no PluginSession escape hatch, registry or transport/client redesign.

Validation alone is the smaller alternative and fixes the malformed-config acceptance, but retains per-endpoint interpretation and the hidden runtime GET recovery. Cold method preparation addresses the same missing admission/preparation boundary. Expected benefit is deterministic rejection of malformed configuration plus removal of that repeated parse. No latency or allocation benchmark is claimed; extension-method clones may still own storage.

Preserve existing zero-limit/path diagnostics and their precedence, enabled/disabled semantics, schema-to-Controller-to-Gateway parity, stage admission, original entry ordinals and generic fail-closed behavior. Known disabled configs remain inert and disabled unknown types still fail the existing front gate. Do not change which valid methods operators may select, add probe bodies or redefine the absent-override contract. Preserve request path/query handling, hop-by-hop and body-header removal, endpoint ordinals, global rate/concurrency/endpoints limits, bounded diagnostic body prefixes, partial results, deadlines, cancellation cleanup and access-log ownership.

The original all-endpoint-status-tls-identity regression guard explicitly accepts per-invocation endpoint clients to prevent same-authority pooling from probing the wrong socket. Keep that decision, canonical Service-port proof, BackendTLSPolicy/current-generation checks, TLS identity precedence, pinned resolution, canonical egress checks and fixed redacted failures. The current transport client_and_url and fan-out permit/timeout owners were inspected; this finding provides no permission to pool clients or alter those lifetimes. ARCH050 concerns repeated schema validation within one immutable resource invocation, not malformed-method acceptance or this runtime preparation owner. Existing AI/WAF/session and credential findings are outside scope.
