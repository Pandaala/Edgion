# Keep OIDC material semantics out of the generic Secret lifecycle

SecretHandler::validate_oidc_secret_shape at secret.rs:94–119 interprets any reverse dependency whose ResourceRef.kind is EdgionPlugins as an OIDC requirement. It then looks for a union of clientSecret/client_secret/sessionSecret/session_secret/secret. The generic SecretRefManager records resource-level wakeup dependencies, without a plugin variant or owning field. BasicAuth, OIDC, TLS material and other consumers deliberately share it. A resource-kind dependency cannot establish an OIDC field contract.

A concrete supported witness is an enabled BasicAuth entry referencing a present same-namespace Secret containing only username and password. BasicAuth resolve_group reads those exact keys through canonical read_secret_utf8; fetch_bound_secret registers the EdgionPlugins owner in the same reverse index before authorization/lookup. The existing real test test_parse_resolves_basic_auth_users_and_registers_refs at edgion_plugins_test.rs:1121–1184 successfully resolves both users and asserts those edges. On a subsequent valid Secret update, SecretHandler::parse normalizes/stores the Secret and calls the OIDC check at179; normal processing also calls on_change, which repeats it at199. With WARN enabled, both sites report that a valid BasicAuth Secret lacks OIDC-compatible fields. Authentication behavior is not claimed broken, and no incident or measured overhead is asserted.

This is avoidable ownership leakage, not a logging-style preference. Every new non-OIDC Secret consumer currently inherits a false OIDC assumption unless it happens to use one of the unrelated aliases. Conversely the union cannot distinguish an OIDC client field from a session field. OpenidConnect's existing owning-field resolver already separates client aliases from session aliases and uses read_secret_utf8, which checks UTF-8 and rejects whitespace-only values. Generic has_non_empty_secret_field instead accepts arbitrary nonempty bytes. The Secret lifecycle is therefore an incomplete parallel policy owner whose available inputs cannot express its stated requirement.

Remove the OIDC inference and its two calls from the generic Secret handler; remove its private key helper and obsolete helper-only tests if no other genuine consumer remains. The handler should own normalization, store publication and dependency wakeups. Any retained OIDC material diagnostic belongs in the existing OpenidConnect bound-field resolver or its existing material/status contract, after the actual field and authorization outcome are known. Reuse the canonical UTF-8 reader and distinct client/session alias sets; do not add an unconditional new warning, infer material errors from dependency unavailability, expose credential bytes, or change current OIDC failure/fallback semantics. A purpose-tagged second dependency index or a Secret-time rescan of all plugin resources would duplicate ownership and expand this small fix unnecessarily.

Preserve stringData-over-data precedence and normalization, init accumulator idempotence and authoritative replacement, store visibility before dependent processing, raw/default resource wakeup identity, ordinary and typed frontend CA edges, deduplication, and delete/recreate recovery. Every runtime dependent is still requeued through the existing single serial queue. Keep bound-reference authorization and registration-before-lookup order, redaction and binary-owned logging, no request-path allocations, the existing body/TLS boundaries, and no new metric or schema/transport field.

Actual Secret tests cover normalization and nested RequestAccessPolicy/frontend-CA delete/recreate edges; the BasicAuth test above demonstrates the valid non-OIDC material and shared edge. These bodies were read, not executed. Future verification should exercise the real enabled BasicAuth resolver followed by Secret processing with a scoped tracing capture, asserting no OIDC-material warning while credential refresh and requeue still occur. Retained OIDC diagnostics, if required, should cover separate client/session aliases, empty/whitespace/invalid-UTF-8 material and authorization-before-read without changing fallback behavior. Existing init/delete/normalization tests remain the lifecycle guards; no test should merely mirror the removed union predicate.

Original Secret architecture and OIDC review index, dependency-error projection and empty-resolved-secret fallthrough decisions were read. They preserve safe consumer-owned resolution and do not justify classifying every EdgionPlugins Secret as OIDC. Existing findings and pending tasks were searched by symbol, warning literal and consumer behavior; no same-root-cause finding was found.
