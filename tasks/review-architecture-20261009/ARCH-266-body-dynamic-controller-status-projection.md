# ARCH-266 — Dynamic status assertions must select their Controller and attachment

Several dynamic status readers bypass the existing distinction between complete diagnostic status and the observation owned by the test's Controller. Two EdgionPlugins readers assume flat conditions and fail on correct Kubernetes envelopes. Three AI scenario readers recursively search the complete resource, so an unrelated Controller or attachment can satisfy an individual status barrier. These are different manifestations of one missing test-owned status projection boundary, not requests to change the producer's status format.

The original BodyDynamic site is fetch_body_dynamic_accepted in edgion-tests/src/client/suites/edgion_plugins/body_plugins.rs:1784-1816. It indexes body["data"]["status"]["conditions"]. Its rejected suite requires both Accepted=False and the existing updated-body business assertion after the invalid DSL generation. The same flat lookup occurs in fetch_ep_condition at edgion-tests/src/client/suites/edgion_plugins/edgion_config_data_status/dynamic.rs:24-61. PmdRefFlap immediately calls its initial suite, which requires Accepted=True and ResolvedRefs=True; subsequent suites preserve Accepted=True, require InvalidEdgionConfigDataRef during the missing-reference phase, and verify recovery. A correct Kubernetes EdgionPlugins response instead carries those conditions in the selected controllers[].status payload. Body fails if it reaches rejection; Pmd fails at its initial assertion. These are conditional source witnesses given the correct selected observation, not evidence that a complete current Kubernetes run or earlier Body transitions passed.

The producer deliberately preserves this shape. ResourceProcessor projects the selected Kubernetes observation into native working status, computes the local verdict, merges it into controllers[], captures typed spec.currentStatus, restores complete status and publishes the complete object to ServerCache. configserver_handlers.rs::get_resource returns that cache object through AdminState::cache_get_resource; types.rs:280-346 serializes and parses without flattening status. EdgionPlugins and EdgionBackend use the private Kubernetes envelope, while FileSystem/etcd recompute native local status. Route parents and Policy ancestors retain their native attachment arrays and preserve foreign entries in complete diagnostic status. The original deployment-partitioned and canonical-parent ownership decisions explicitly require this complete/current split.

The additional AI sites are has_condition and its wait callers in edgion-tests/src/client/dynamic/scenarios/ai_backend_lifecycle.rs:243-255,279-296; ai_backend_policy_integration.rs:225-237,261-279; and ai_backend_weighted.rs:143-155,179-187. They accept any matching type/status/optional reason found recursively anywhere in the resource. Lifecycle checks EdgionBackend conditions, HTTPRoute parents and EdgionBackendTrafficPolicy ancestors; PolicyIntegration checks EdgionBackend, HTTPRoute, BackendTLSPolicy and EdgionBackendTrafficPolicy; Weighted checks HTTPRoute. A retained foreign envelope observation can satisfy a backend condition while the selected observation disagrees or is absent. Likewise, a foreign-controller or different parent/ancestor entry can satisfy an attachment condition. Foreign preservation is required by the producer and is therefore real accepted input, not malformed JSON invented solely for a test. This proves loss of the individual barrier's intended ownership; independent traffic, publication and other assertions may still fail, so this finding does not claim that an entire matrix necessarily passes incorrectly.

Kubernetes execution is declared: k8s_dynamic_scenarios.tsv registers BodyDynamic, PmdRefFlap, AiBackendLifecycle and AiBackendWeighted, and the wrapper supplies EDGION_TEST_K8S_MODE=true. AiBackendPolicyIntegration has its separate Kubernetes runner invocation, with the same mode supplied by run_test_client.sh and a configured policy-integration-gateway name. The canonical Kubernetes Controller configuration selects edgion.io/gateway-controller. Existing ACME/status-seeding and encrypted-health fixture exceptions do not exempt these readers. Direct/local invocation also remains supported; complete native Route and Policy diagnostic status can retain foreign attachment entries, so attachment selection is required there as well.

For Body and Pmd, reuse dynamic::status::conditions before selecting the requested condition. That existing test-owned helper chooses native local conditions or the selected Kubernetes Controller envelope and fails on a missing selected observation or conditions. For AI backend simple-resource conditions, reuse the same projection. Preserve authenticated requests, non-success and malformed-response failure, every existing status/reason predicate and all business assertions. A missing condition or selected observer must remain an error or unsatisfied bounded wait, never successful rejection. Preserve Body's capped H1/H2, restored body and last-known-good assertion; preserve Pmd's initial, invalid-reference and recovery checks.

Do not apply the simple-resource helper to Route parents or Policy ancestors. Replace the recursive searches with explicit selection of the scenario's intended parent or ancestor and selected controllerName, then inspect only that entry's conditions. Use the actual fixture Gateway identity, including PolicyIntegration's existing gateway_name() selection, and reuse ParentReference::canonical_identity for group/kind/namespace defaults and exact name, section and port dimensions rather than inventing another reference grammar. Require the intended entry and reject ambiguous duplicates. Extend the existing test-owned status module only with the bounded attachment selection needed by these real callers; do not redirect them to the broader status helpers' current any-parent/any-ancestor search, which has the same ownership weakness. Multiple relevant attachments require an explicit scenario predicate, not an arbitrary first entry or recursive any-condition match. Keep controller identity tied to the declared topology.

Flattening the Controller API would violate complete diagnostic history and foreign preservation. Reading an arbitrary controller entry, accepting an arbitrary same-name Gateway or switching to an unqualified conditions search only hides the mismatch. This bounded correction changes assertion inputs, not admission, status producers, currentStatus authority, persistence, conf_sync, Gateway routing, body ownership, TLS, workqueues, observability or fixture scope. ARCH264 initialization/restoration, ARCH265 cleanup-result ownership and ARCH296 listener-port ownership remain separate causes.

Existing status-helper tests select the matching Controller and preserve native status. Actual producer tests preserve foreign envelopes/attachments and the complete/current split, while canonical parent-identity tests cover defaults and every attachment dimension. The complete Pmd phase suite and scenario, Body's actual dynamic suite, all three AI implementations and their embedded tests were read; these readers do not currently have focused envelope/attachment ownership regressions. Future verification should pass native and partitioned responses through the real Body/Pmd helpers, include contradictory foreign observations and a missing selected Controller, and exercise AI barriers with foreign-controller, wrong-parent/ancestor and ambiguous matching entries. Preserve original condition reasons and every existing traffic/status assertion. No test, build, network operation or repository mutation occurred.
