# Distinguish delegation rejection from an unknown backend RPC

`GrpcDelegationTestSuite::test_out_of_scope_child_rule_unimplemented` in `edgion-tests/src/client/suites/grpc_route/delegation.rs` calls `/test.OtherService/Whatever` and passes solely when tonic reports `Unimplemented`. The file explicitly says this service does not exist on the test server and that rejection must happen before any backend is contacted. However, the observed gRPC status does not establish that boundary: an unimplemented backend RPC can also return status 12. The existing local child fixture points this rule at `child-grpc-svc:30021`; the Kubernetes fixture points it at the same real test server through `test-grpc:30021`. Neither backend implements `test.OtherService`.

The actual production owners expose the missing attribution boundary. Controller `grpc_route_delegation::merge_match` requires the child's explicit service to equal its delegated scope, and terminal-rule flattening drops `NotContained` matches. The Gateway's unmatched-native-gRPC path separately records `RouteNotFound` and sends status 12. The test server registers `test.TestService` and `grpc.health.v1.Health`. Its repository-generated TestService dispatcher has a status-12 fallback for unsupported methods within the registered service; this establishes a backend status-12 producer, but does not establish how the transport router dispatches the distinct unregistered `/test.OtherService/Whatever` service. Do not present that generated fallback as a source-proven forwarded execution of this exact negative probe. The status-only assertion lacks the canonical evidence required to identify the Gateway rejection owner. This is an assertion gap, not a demonstrated current false pass, a claim that flattening forwards the forbidden rule, or an observed delegation escape.

Keep the same negative RPC and require the existing canonical evidence that this particular request was rejected at Gateway route selection. Attach a unique valid W3C `traceparent` using `traceparent_for_marker`, opt into the existing integration-only `access_log: test_store` projection, and query the selected Gateway through `TestContext::access_log_client`. Require the trace-correlated entry to contain the existing error diagnostic `RouteNotFound`, in addition to the current exact `Unimplemented` result. Missing evidence, authentication failure, retrieval failure or polling deadline must fail. Bound the complete observation within the current thirty-second case deadline; do not turn the helper's retry count into an additional unbounded wait.

This is feasible without a new instrumentation owner. `pg_logging` stores the canonical terminal entry under the initialized W3C identity when integration mode and the existing test-store header are selected. `AccessLogClient` already supplies marker conversion, authenticated lookup, bounded retrieval and exact diagnostic matching. The actual request-entry unit case distinguishes unmatched-native status 12 with `RouteNotFound` from the frontend HTTP/2 rejection and HTTP fallback branches. Reading this existing projection preserves binary-owned logging and adds no request tracing, metric, response disclosure or parallel log sink.

Preserve all five static case identities, delegated SayHello and inherited-header checks, clean StreamNumbers completion, parent `PartiallyInvalid`/`ResolvedRefs` assertions, reverse-lock status, and the separate dynamic phase cases. The parent status test remains useful independent Controller evidence; it does not prove which owner returned this RPC's status, and this finding does not claim the entire suite necessarily passes a broken generation. An alternative is to change both fixture trees to probe an already implemented out-of-scope service with its correct codec, but that changes the scenario's authored service identities and offers no need to bypass the existing access-log owner.

Future verification should reject a forwarded status-12 response lacking the Gateway no-route diagnostic, accept the actual trace-correlated rejection, and fail absent diagnostic evidence.
