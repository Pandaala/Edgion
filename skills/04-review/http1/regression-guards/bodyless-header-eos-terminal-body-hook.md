# Header EOS Drives the Terminal Response-Body Hook

## Conclusion

The Edgion Pingora fork treats a final upstream `Header(_, true)` as the same response-body
terminal boundary as `Body(None, true)`. When `response_filter` accepts the header, it calls
`upstream_response_body_filter` exactly once with
`body = None` and `end_of_stream = true`, allowing generic streaming processors to finalize state
or synthesize a bounded replacement body. This is a transport-level contract, not an Anthropic
special case.

The decision uses the upstream task's actual EOS bit. `Content-Length: 0` is not a substitute,
because an H2 HEADERS frame may declare zero length while leaving the stream open.

## Lifecycle Rules

- H1, H2, and custom upstreams share the same synthetic terminal body-hook dispatch.
- Informational headers do not finalize the response; 101 continues through the upgrade path.
  A source that reports a completed Upgrade as `Header(101, true)` is normalized by the custom
  pump into `Header(101, false)` + `Done`, so the terminal hook still fires exactly once and the
  released bytes keep the upgraded body variant. See
  [custom-terminal-101-normalized-before-dispatch.md](https://github.com/Pandaala/pingora/blob/edgion_v3/edgion-changes/review/http1/custom-terminal-101-normalized-before-dispatch.md).
- The header's final `response_filter` runs before synthetic terminal dispatch. A local reply,
  denial, or header-filter error prevents the body hook and all of its side effects.
- A filter-produced current chunk precedes chunks emitted through `ResponseBodySink`.
- The synthetic current chunk has the same unbudgeted semantics as mutating the current bytes of a
  regular `Body(None, true)` task. Only additional `ResponseBodySink::push` chunks consume the
  bounded per-batch emission budget.
- A terminate signal at this already-natural terminal boundary is consumed instead of aborting a
  reusable connection.
- A generated body changes `Header(_, true)` to `Header(_, false)` and moves the sole EOS marker to
  the final emitted body chunk.
- Cache admission stores that transformed sequence. Cache hits replay it without invoking the
  upstream hook a second time. Live output, cache misses, and cache hits all apply the same
  downstream body-filter chain and receive the same terminal EOS callback.
- The final downstream `response_filter` runs exactly once per client response. When terminal
  admission switches to streaming miss readback, the pump carries the already-filtered downstream
  header into that readback instead of invoking the hook again; a bare "filter done" flag is
  insufficient because the cached header intentionally contains the pre-downstream-filter form.
- Cache policy is evaluated before the downstream response filter. Terminal admission is completed
  afterward so cached metadata and bytes use a reconciled `Content-Length`.
- Internal cache-control responses consumed by revalidation or stale serving are not forwarded
  response representations and are outside the response-body hook lifecycle.
- `HEAD`, 1xx, 204, and 304 suppress generated bytes. The final downstream status is checked after
  `response_filter` as well as after the upstream header filter, and the suppression decision
  persists across cached body tasks.
- H1 adds chunked framing when a header-EOS response gained a body and has no explicit framing;
  late body suppression removes framework-generated or status-illegal transfer framing.
- A cache hit whose final response filter makes the response bodyless ends on the header and does
  not read or emit the cached body.
- Downstream header completion never marks the upstream source complete. A bodyful origin changed
  to 204/304 is still drained through its real EOS and completes cache admission; its suppressed
  Body/Trailer/Done tasks are dropped without creating another downstream terminal callback.
- H1 framing is reconciled after the final header filter. Framework-added chunked framing and an
  application `Content-Length` are mutually exclusive. A stale origin `Content-Length`, including
  zero, is removed when terminal synthesis changes the actual body size; H2 and custom paths use
  the same reconciled metadata.
- A source failure after a body-forbidden downstream terminal prevents upstream reuse but does not
  replace the already-complete downstream response or create another terminal task. Any incomplete
  cache admission is disabled so its miss writer and lock are released.
- A body-forbidden downstream terminal still lets cache admission and predicted-size accounting
  observe each upstream follow-up task once. The suppression guard then drains that task's sink
  extras before returning so a later task in the same pump batch cannot observe them again. See
  [gw-16-suppressed-sink-extras-drained.md](gw-16-suppressed-sink-extras-drained.md).

## Rejected Fixes

- Checking only `Content-Length: 0` misses other H1 bodyless framing and misclassifies an open H2
  stream.
- Emitting an Anthropic envelope from the response-header plugin bypasses the generic processor,
  cache, framing, and EOS contracts.
- Calling the hook without migrating Header EOS produces a body after an already-terminal header.
- Skipping the streaming-miss `response_filter` with only a boolean loses header mutations made by
  the live call; the filtered terminal header must be preserved for downstream readback.
- Fixing only the live origin path leaves cache-hit replay capable of sending a forbidden body.

## Regression Boundary

Fork coverage must include H1 downstream framing and reuse, H2 upstream END_STREAM, a real custom
connector, cache miss/hit byte identity, output order and budget, terminate handling, body-forbidden
statuses including both directions of late response-filter mutation, source drain after a bodyful
response becomes bodyless, terminal hook ordering, downstream-filter miss/hit identity, and no
second Done callback. Edgion integration coverage must verify bodyless Anthropic fixed and SSE
responses over H1 and H2 clients, including bounded OpenAI-compatible envelopes, provider-header
isolation, final stream classification, and the translation-failure signal only where the
translator classifies the condition as a failure.

Re-open this finding if any final upstream Header EOS path skips the terminal hook, emits more than
one wire EOS, sends a body forbidden by the final downstream method/status, or re-runs the upstream
hook on a cache hit.
