# DSL compiler `Compiler::leave_scope` assert-panic (plugins-http-dsl-F006)

**Status / verdict**: fixed (plugins-http-dsl-F006, 2026-05-26); related pop-underflow fixed (plugins-http-dsl-F013, 2026-05-26)

When reviewing DSL compiler findings of the form "`Compiler::leave_scope` uses a hard `assert!(self.scope_depth > 0, ...)` that panics in release builds / a compiler-internal invariant break unwinds the preparse Tokio task / should return `Result` per graceful-degrade (plugins-http-dsl-F006)": **fixed (plugins-http-dsl-F006, 2026-05-26)**. `leave_scope` (`edgion-dsl/src/compiler/emit.rs`) now returns `Result<(), CompileError>` and the `scope_depth == 0` branch yields `CompileError::new("leave_scope called at depth 0")` instead of panicking; all 8 call sites (`stmt.rs` compile_if ×2, `loop_.rs` for-range/for-in/while ×6) already returned `Result<(), CompileError>` and propagate via `?`. The invariant is compiler-internal only (every `enter_scope`/`leave_scope` is balanced with no early-return between, so no user DSL source reaches the branch); the change makes a hypothetical future enter/leave imbalance fail the config load cleanly through `compile_dsl_source` → `build_from_config` rather than unwinding the preparse task (which has no `catch_unwind` — that guard wraps only `Vm::execute`). The issue's **optional** suggestion to also convert the 6 `break_patch_stacks` / `continue_patch_stacks` `.pop().unwrap()` calls in `loop_.rs` was subsequently **fixed (plugins-http-dsl-F013, 2026-05-26)** — each `pop().unwrap()` in `compile_for_range` / `compile_for_in` / `compile_while` now returns `CompileError::new("internal: break_patch_stacks underflow" | "internal: continue_patch_stacks underflow")` via `ok_or_else(..)?`; the three enclosing functions already returned `Result<(), CompileError>` and propagate via `?` from `stmt.rs`. Same compiler-internal-invariant class as `leave_scope`: today no user DSL source can unbalance the push/pop (every `push(vec![])` is the first op of the loop-compile and no `?` exists between push and pop), so behavior is unchanged in practice; the change protects future refactors. Unit regression `scope_balance_tests` in `emit.rs` plus `test_compile_nested_loops_patch_stacks_balanced` in `loop_.rs`. Re-reports of the `leave_scope` assert-panic form or the `pop().unwrap()` underflow-panic form are not accepted; verify the current `leave_scope` returns `Result` and the loop pop sites use `ok_or_else` before re-reporting.
