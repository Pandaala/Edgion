# Rust coding rules

> Goal: keep the code consistent, readable, and safe.

## Rule 1: use `use` imports; avoid long inline paths

When referencing types, functions, or constants, **always** import them with `use` at the top of the file and use the short name at call sites.

```rust
// Correct: import at the top, concise at the call site
use edgion_resources::constants::annotations::edgion;
use edgion_resources::resources::common::ParentReference;
use edgion_resources::resources::link_sys::SystemConfig;

let proxy_proto = annotations.get(edgion::PROXY_PROTOCOL);
let config = SystemConfig::Webhook(config);

// Wrong: long inline path hurts readability
let proxy_proto = annotations.get(edgion_resources::constants::annotations::edgion::PROXY_PROTOCOL);
let config = edgion_resources::resources::link_sys::SystemConfig::Webhook(config);
```

**Criterion**: any path longer than 2 segments (`crate::a::b::Item`) should be imported.

**Exceptions**:
- Disambiguating same-named types (e.g., `std::io::Error` vs `crate::Error`) may use the full path
- Paths inside macros (code generated by proc macros)

## Rule 2: no unwrap() / expect() without context

Bare `unwrap()` is forbidden in production code. `expect()` is only allowed when the logic guarantees no panic, and the reason **must** be written out.

```rust
// Correct: expect explains why no panic is possible
let tail = self.tail.expect("tail must exist when len > 0");

// Correct: handle the error with ? or match
let value = map.get(&key).ok_or_else(|| Error::NotFound(key))?;

// Wrong: bare unwrap with no context on crash
let value = map.get(&key).unwrap();

// Wrong: expect with no reason
let value = map.get(&key).expect("failed");
```

**Exceptions**:
- Test code (`#[cfg(test)]`) may use `unwrap()` freely
- Statically guaranteed cases (e.g., `Regex::new(r"literal")` where the regex is known valid at compile time)

## Rule 3: use Clone judiciously

Avoid unnecessary `.clone()`, especially on large structs. Prefer references or `Arc`.

```rust
// Correct: cloning an Arc is cheap
let store = self.store.clone(); // Arc<RwLock<T>>

// Correct: clone only when an owned value is needed
let name = resource.name().to_string();

// Suspicious: cloning a big struct only to read
let route = big_route_config.clone();
let name = route.name; // Only `name` is needed; no need to clone the whole struct
```

## Rule 4: error messages must be actionable

Error messages should contain: **what failed** + **context** + **possible remedy** (when applicable).

```rust
// Correct: includes context and suggestion
format!(
    "Cannot create work directory {}: {}\nPlease check permissions or specify a different directory with --work-dir",
    path.display(), e
)

// Wrong: no context
format!("IO error: {}", e)
```

## Rule 5: prefer graceful degrade over panic in long-running paths

In **long-running paths** (data plane request/response/body filters, TLS proxy, stream proxy, plus control-plane reconcile loops / watchers / periodic tasks), an unreachable "should-not-happen" branch should normally **graceful-degrade**, not panic.

A graceful-degrade branch does three things:
1. Does **not** panic / abort.
2. Falls back to a safe default behavior (return `None`, fall through to the rule's `default`, skip the bad entry, etc.).
3. Leaves an observability trail — data plane uses `plugin_log.push_err("<static kind>")`; control plane uses `tracing::warn!`/`error!` with enough context.

```rust
// Correct: data-plane fallback for an invariant the config layer should have caught
if let Some(replace) = transform.replace.as_ref() {
    return match compiled_replace {
        Some(re) => Some(re.replace_all(value, replace.with.as_str()).to_string()),
        None => {
            // Invariant: validate() compiles every Replace pattern; reaching
            // here means the config bypassed validation. Fail-open via default.
            plugin_log.push_err("transform regex missing");
            None
        }
    };
}

// Wrong: panic on the data plane — a misconfig kills every in-flight request
None => panic!("compiled_transform_regex missing"),

// Wrong: debug_assert!(false, ...) — not the project idiom, zero sites in src/
// after the graceful-degrade audit cleanup; in dev/CI it crashes the test (kube-rs
// reconcile has no catch_unwind, so the controller pod dies), in release it is a
// no-op that adds nothing the existing graceful branch doesn't already have
None => {
    debug_assert!(false, "compiled_transform_regex missing");
    None
}
```

**Exceptions** (panic / `expect` / `unreachable!()` remain appropriate):
- **Startup / one-shot init** — `main.rs`, CLI subcommand entry points, config loading, `ConfigCenter::new`, anything that runs once before the event loop spins up. Failing fast lets K8s restart the pod.
- **True exhaustive-match dead arms** — closed-enum `match` where the trailing arm is logically unreachable; `unreachable!()` is the right tool there.
- **Data corruption / broken invariant where continuing is less safe than crashing** — e.g., a memory data structure's internal consistency has already been violated. Document the reasoning in a comment.
- **Test code** (`#[cfg(test)]`) — not constrained.

When in doubt, prefer graceful-degrade — Edgion is a gateway, a panicked request path is a 5xx for the user. Cross-codebase audit follow-up is tracked in `tasks/todo/graceful-degrade-audit.md`.

**Related time-delta idiom**: in long-running paths, never use `prior.elapsed()` or `now.duration_since(prior)` on an `Instant` — both can panic on non-monotonic clock skew (AMD EPYC TSC, linkerd2-proxy #7748). Use `Instant::now().saturating_duration_since(prior)` (or `now.saturating_duration_since(prior)` if `now` is already bound). Returns `Duration::ZERO` instead of panicking and is identical on well-behaved clocks. See [04-review/SKILL.md](../04-review/SKILL.md) for the closed audit (57 sites).

## Rule 6: prefer canonical utilities over local copies

Before writing a parsing, formatting, or validation helper, search the owning crate and
the lower layers it is allowed to depend on. Reusing the canonical implementation keeps
behavior consistent and lets fixes propagate.

Known canonical helpers (non-exhaustive):

| Helper | Location | Notes |
|--------|----------|-------|
| `parse_duration` | `edgion-resources/src/duration.rs` | Returns `Result<Duration, ParseDurationError>`; supports `ms/s/m/h/d` and combined forms like `"1h30m"`, `"2d12h"`; rejects negatives. **Do not** reimplement — RateLimitLocal had its own copy that diverged in unit set, error type, and combined-format support, then had to be migrated back. |
| `MetadataFilter` matching | `edgion-controller/src/conf_mgr/metadata_filter.rs` | K8s label / namespace selector evaluation |
| Real-IP extraction | `edgion-gateway/src/util/real_ip_extractor.rs` | Trusted proxy / `X-Forwarded-For` parsing |

If you genuinely need different behavior, extend the canonical rather than forking.
Preserve the workspace DAG: `edgion-dsl → edgion-resources → edgion-common →
{edgion-gateway, edgion-controller, edgion-cli}`. In particular,
`edgion-resources` must not import `edgion-common`; that would create a dependency cycle.

## Checklist

Use during code review:

- [ ] Any inline `crate::` path longer than 2 segments? Extract to a `use` import
- [ ] Any bare `unwrap()`? Switch to `?` / `expect("reason")` / `match`
- [ ] Do `expect()` messages explain why panic is impossible?
- [ ] Any unnecessary `.clone()`? Can a reference or `Arc` be used instead?
- [ ] Do error messages carry enough context for troubleshooting?
- [ ] New parsing/validation helper? Search the current crate and permitted lower-layer crates; do not reverse the workspace DAG

These are review conventions rather than compiler-enforced lints. Verify changes with
the project commands (`cargo fmt --all`, workspace check/clippy, and the relevant custom
guards) in addition to manual review.
- [ ] New `panic!` / `unreachable!()` / `debug_assert!(false, ...)` on a long-running path? Check Rule 5 exceptions — most should be graceful-degrade + `push_err`/`tracing::warn!`
