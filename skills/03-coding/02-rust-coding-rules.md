# Rust coding rules

> Goal: keep the code consistent, readable, and safe.

## Rule 1: use `use` imports; avoid long inline paths

When referencing types, functions, or constants, **always** import them with `use` at the top of the file and use the short name at call sites.

```rust
// Correct: import at the top, concise at the call site
use crate::types::constants::annotations::edgion;
use crate::types::resources::common::ParentReference;
use crate::types::resources::link_sys::SystemConfig;

let proxy_proto = annotations.get(edgion::PROXY_PROTOCOL);
let config = SystemConfig::Webhook(config);

// Wrong: long inline path hurts readability
let proxy_proto = annotations.get(crate::types::constants::annotations::edgion::PROXY_PROTOCOL);
let config = crate::types::resources::link_sys::SystemConfig::Webhook(config);
```

**Criterion**: any path longer than 2 segments (`crate::a::b::Item`) should be imported.

**Exceptions**:
- Disambiguating same-named types (e.g., `std::io::Error` vs `crate::Error`) may use the full path
- Paths inside macros (code generated by proc macros)

## Rule 2: no unwrap() / expect() without context

Bare `unwrap()` is forbidden in production code. `expect()` is only allowed when the logic guarantees no panic, and the reason **must** be written out.

```rust
// Correct: expect explains why no panic is possible
let tail = self.tail.expect("tail must exist when len > 0");

// Correct: handle the error with ? or match
let value = map.get(&key).ok_or_else(|| Error::NotFound(key))?;

// Wrong: bare unwrap with no context on crash
let value = map.get(&key).unwrap();

// Wrong: expect with no reason
let value = map.get(&key).expect("failed");
```

**Exceptions**:
- Test code (`#[cfg(test)]`) may use `unwrap()` freely
- Statically guaranteed cases (e.g., `Regex::new(r"literal")` where the regex is known valid at compile time)

## Rule 3: use Clone judiciously

Avoid unnecessary `.clone()`, especially on large structs. Prefer references or `Arc`.

```rust
// Correct: cloning an Arc is cheap
let store = self.store.clone(); // Arc<RwLock<T>>

// Correct: clone only when an owned value is needed
let name = resource.name().to_string();

// Suspicious: cloning a big struct only to read
let route = big_route_config.clone();
let name = route.name; // Only `name` is needed; no need to clone the whole struct
```

## Rule 4: error messages must be actionable

Error messages should contain: **what failed** + **context** + **possible remedy** (when applicable).

```rust
// Correct: includes context and suggestion
format!(
    "Cannot create work directory {}: {}\nPlease check permissions or specify a different directory with --work-dir",
    path.display(), e
)

// Wrong: no context
format!("IO error: {}", e)
```

## Checklist

Use during code review:

- [ ] Any inline `crate::` path longer than 2 segments? Extract to a `use` import
- [ ] Any bare `unwrap()`? Switch to `?` / `expect("reason")` / `match`
- [ ] Do `expect()` messages explain why panic is impossible?
- [ ] Any unnecessary `.clone()`? Can a reference or `Arc` be used instead?
- [ ] Do error messages carry enough context for troubleshooting?
