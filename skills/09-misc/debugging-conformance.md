# Conformance Test Debugging Guide

This document explains how to quickly diagnose conformance test failures, covering log collection, rv/sv tracing, and recognizing common failure patterns.

## Key prerequisite: logs are in files, not in stdout

`kubectl logs` (`orbstack-dev.sh logs`) only sees process stdout, where there is very little output (process crashes / panics).
All valuable logs live in files inside the pod:

| Log | Path inside pod | Meaning |
|-----|-----------------|---------|
| gateway system log | `/usr/local/edgion/logs/edgion-gateway.<YYYY-MM-DD>` | Configuration sync, route registration, startup/shutdown |
| controller system log | `/usr/local/edgion/logs/edgion-controller.<YYYY-MM-DD>` | Resource processing, sv generation, gRPC sync |
| access log | `/usr/local/edgion/logs/edgion_access.log` | One JSON entry per request, including sv, stage_logs, upstream |
| TLS access log | `/usr/local/edgion/logs/tls_access.log` | TLS handshake / route-match results |

Use the new commands of `orbstack-dev.sh` to read them (see below); no manual `kubectl exec` needed.

## The rv / sv / access log triple

The three form a tracing chain across components:

```
K8s resource change
  │  rv (resource_version, from metadata.resource_version)
  ▼
Controller process_resource()
  │  sv (sync_version, generated by controller, written to annotation + gRPC event)
  ▼
Gateway routing-table update
  │  sv (written into MatchInfo, attached to access log of every request)
  ▼
access log entry  →  match_info[].sv = <sv>   (array root → leaf; the last element is the leaf route)
```

**Usage**:
- A request misbehaves → find the `match_info[].sv` value in the access log (one per matched delegation level)
- Use `find-sv <sv>` to find the corresponding resource-processing event in the controller log to see what configuration was synced at that time
- Then use the `rv` value to find the original K8s resource change in the controller log

## Quick troubleshooting workflow

### Step 1: Check K8s resource state

```bash
# Are pods Ready, GatewayClass/Gateway Accepted?
./scripts/orbstack-dev.sh status

# Are route resources Accepted / ResolvedRefs=True?
./scripts/orbstack-dev.sh route-status grpc   # only GRPCRoute
./scripts/orbstack-dev.sh route-status all    # all
```

If a route shows `Accepted=False` or `ResolvedRefs=False`, the issue is in the control plane — no need to look at data-plane logs.

### Step 2: Look at the gateway system log

```bash
# Last 80 lines (any errors during config sync?)
./scripts/orbstack-dev.sh file-log g --tail 80

# Filter by keyword
./scripts/orbstack-dev.sh file-log g --grep "error\|warn\|No matching\|tls_route"
```

### Step 3: Look at the access log

```bash
# Last 30 requests (JSON format)
./scripts/orbstack-dev.sh access-log --tail 30

# Filter by host
./scripts/orbstack-dev.sh access-log --grep "foo.com"

# Filter by path
./scripts/orbstack-dev.sh access-log --grep "/detect-misdirected"
```

Key access-log fields:
- `status` — HTTP status code (200/421/404, etc.); for gRPC, status=200 but check the `grpc_status` field
- `match_info[].sv` — the associated sync_version (per matched level)
- `stage_logs` — execution result of each plugin, formatted as `OK u=alice; ` or `ERR ...`
- `upstreams` — upstream addresses, latency, retry counts
- `sni` — TLS SNI (key when debugging 421 issues)

### Step 4: Use sv to trace the configuration source

```bash
# Take the sv from the access log (e.g. sv=42) and trace across logs
./scripts/orbstack-dev.sh find-sv 42
```

The output has three sections: gateway log entries matching sv=42, controller log entries matching it, and the corresponding request in the access log.

### Step 5: For TLS-related failures, look at tls_access.log

```bash
./scripts/orbstack-dev.sh tls-log --tail 30
./scripts/orbstack-dev.sh tls-log --grep "foo.com"
```

tls_access.log fields: `sni_hostname`, `gateway_name`, `status` (`Connected` / `NoMatchingRoute`).

### One-shot snapshot (dump immediately after a failure)

```bash
# Collect all relevant state to stdout; can be redirected to a file
./scripts/orbstack-dev.sh dump-debug > /tmp/debug-$(date +%H%M%S).txt
```

Includes: Pods + GatewayClass + conditions of all routes + recent gateway/controller logs + recent access-log entries.

## Common failure modes per profile

### GATEWAY-GRPC

**Symptom**: `Internal(13)` instead of the expected status code

| Root cause | How to confirm | Log keywords |
|------------|----------------|--------------|
| Hostname mismatch but the gateway closes the stream directly without sending trailers | access log: status=200 but grpc_status=13; gateway log: no unimplemented-related output | `send_grpc_error_three_frame` |
| The route is not registered at all | Look at `route-status grpc` Accepted state | `No matching GRPCRoute` |
| Upstream H2C connection failure | The `upstreams` field of the access log contains errors | `h2c\|h2 upstream\|connect error` |

**Symptom**: `Unimplemented(12)` is correct, but weight-based routing fails (expected OK(0))

First confirm whether the GRPCRoute resource's `status.conditions` look normal, then check the gateway log for any errors during weight-based backend selection.

### GATEWAY-HTTP

**Symptom**: Should return 421 but returns 200 (MisdirectedRequests)

```bash
# Check the listener's Programmed status
kubectl get gateway same-namespace-with-https-listener \
  -n gateway-conformance-infra \
  -o jsonpath='{.status.listeners}' | jq .

# Check that the sni field in the access log is correctly populated
./scripts/orbstack-dev.sh access-log --grep "detect-misdirected"
# Look at whether the sni field is example.org while host is second-example.org
```

### GATEWAY-TLS (requires the `--tls-only` environment)

```bash
# The most direct log for TLS route-match failures
./scripts/orbstack-dev.sh tls-log --grep "NoMatchingRoute\|foo.com"

# The TLS-route module in the gateway system log
./scripts/orbstack-dev.sh file-log g --grep "tls_route_manager\|passthrough"
```

## Test + log combined workflow

In one terminal run a single test, in another monitor the logs:

```bash
# Terminal 1: run a single test
cd edgion-tests/conformance
GO_RUN_FILTER="TestConformance/GRPCRouteListenerHostnameMatching$" bash scripts/run.sh

# Terminal 2: tail the access log live (you can also look at it after the test finishes)
./scripts/orbstack-dev.sh access-log -f

# Or: dump a snapshot after the test
./scripts/orbstack-dev.sh dump-debug
```
