# 沙盒安全模型

本文档描述 EdgionDSL 脚本执行环境的安全机制，包括资源限制、错误处理策略和各阶段的 API 可用性。

## 安全设计理念

EdgionDSL 的沙盒设计遵循以下核心原则：

**最小能力原则**：脚本在初始状态下没有文件系统访问、没有环境变量读取、没有进程管理操作。所有与网关上下文的交互（读取请求头、拒绝请求等）都必须通过经过审计的内置函数完成，这些函数的行为是可预期且有边界的。出站网络访问仅通过 `http.call()` 内置函数提供，并受到严格的超时限制、响应体大小限制，以及可选的 SSRF 防护（`httpBlockPrivateIps`）。

**纵深防御**：安全保障分为两层。编译期校验在脚本加载时静态检查指令数、变量数、常量池大小等结构性限制，拒绝编译过于复杂或恶意构造的脚本；运行时限制在每次请求执行时动态追踪执行步数、循环迭代次数、函数调用次数等，防止脚本在运行时超出预期资源消耗。两层保护相互补充，单层失效不会导致整体失守。

**Panic 隔离**：VM 的执行函数使用 `std::panic::catch_unwind` 包裹。即使 VM 内部出现不可预期的 panic，也不会传播到网关主进程，网关会根据配置的 `errorPolicy` 优雅降级并记录 panic 信息，以便排查。

**可观测性**：每次执行错误、资源超限或 panic 都会产生结构化日志，包含脚本名称、错误类型和触发原因，便于在生产环境中定位问题。

## 运行时资源限制

以下限制在每次请求执行时独立计算，互不干扰。所有配置字段均位于插件的 `config` 块中。

| 限制 | 配置字段 | 默认值 | 最小值 | 最大值 | 说明 |
|------|----------|--------|--------|--------|------|
| 最大执行步数 | `maxSteps` | 10,000 | 1 | 1,000,000 | 每次执行的总字节码指令数 |
| 最大循环迭代次数 | `maxLoopIterations` | 100 | 1 | 100,000 | 单个循环体的迭代上限 |
| 最大函数调用次数 | `maxCallCount` | 500 | 1 | 100,000 | 内置函数调用总数 |
| 最大栈深度 | `maxStackDepth` | 128 | 1 | 1,024 | 值栈深度 |
| 最大字符串长度 | `maxStringLen` | 8,192 | 1 | 1,048,576 | 字符串拼接结果最大字节数 |

### 各限制详细说明

**maxSteps（最大执行步数）**

每条字节码指令消耗一个步数。步数是对脚本整体计算量最直接的衡量，可以防止无限循环和过度计算。对于典型的请求处理脚本（读取几个头、做条件判断、设置一个头），通常消耗不超过几十步，默认值 10,000 足以覆盖绝大多数场景。如果步数耗尽，VM 抛出 `StepLimitExceeded` 错误。

**maxLoopIterations（最大循环迭代次数）**

对单个 `for` 循环的迭代次数设置上限。例如遍历一个列表时，如果列表元素超过该值，循环会提前终止并抛出 `LoopLimitExceeded` 错误。该限制与 `maxSteps` 协同工作：即使步数未耗尽，单个循环过多的迭代也会被拦截。

**maxCallCount（最大函数调用次数）**

计算整个执行过程中内置函数的调用总次数（包括 `req.header()`、`resp.set_header()`、`json_get()` 等所有内置函数）。该限制防止脚本通过大量函数调用产生放大效应，例如在循环中反复调用开销较高的 API。

**maxStackDepth（最大栈深度）**

VM 使用栈来计算表达式。深度嵌套的表达式（如多层函数调用组合）会消耗更多栈空间。该限制防止恶意构造的深层嵌套表达式耗尽内存。对于正常的业务脚本，128 层栈深度远超实际需要。

**maxStringLen（最大字符串长度）**

限制字符串拼接操作产生的结果最大字节数。如果拼接后的字符串超过该值，VM 抛出 `StringTooLong` 错误。该限制同时也是 `json_get()` 等处理字符串数据的函数的间接约束。注意：该限制针对运行时产生的字符串，不影响编译期常量池中的字符串（由单独的编译期限制控制）。

### 配置示例

```yaml
spec:
  requestPlugins:
    - enable: true
      type: Dsl
      config:
        name: "my-script"
        source: |
          # 脚本内容
        maxSteps: 5000
        maxLoopIterations: 50
        maxCallCount: 200
        maxStackDepth: 64
        maxStringLen: 4096
        errorPolicy: deny
```

生产环境建议使用默认值。只有在脚本确实需要处理较大数据量或较复杂逻辑时，再针对性地调大单个限制，而不是盲目调大所有限制。

## 编译期校验

脚本在加载时（`source` 模式下为首次请求到达时编译，`bytecode` 模式下为网关启动时验证）会执行编译期校验。以下限制在编译阶段静态检查，不通过则拒绝加载脚本。

| 限制 | 默认值 | 说明 |
|------|--------|------|
| 最大指令数 | 1,000 | 编译后的字节码指令总数 |
| 最大局部变量数 | 64 | 局部变量槽位数 |
| 最大常量数 | 256 | 常量池条目数 |
| 单个字符串常量长度 | 4,096 字节 | 单个字符串字面量的最大长度 |
| 常量池总大小 | 32,768 字节 | 常量池所有字符串的总字节数 |
| 最大循环嵌套深度 | 8 | `for` 循环的最大嵌套层级 |
| 正则表达式模式长度 | 1,024 字节 | 单个正则表达式字面量的最大长度 |

编译期校验是一次性开销，脚本通过校验后会被缓存，后续请求直接复用编译结果，不重复编译。

正则表达式在编译期不仅检查长度，还会验证语法合法性，不合法的正则会在脚本加载时直接报错，而不是等到运行时才失败。`.matches()` 方法中使用的正则模式也会在编译期预编译并缓存，避免每次请求重新编译正则。

## 错误策略（errorPolicy）

`errorPolicy` 控制脚本执行出错时的网关行为。错误包括运行时错误（如类型错误、超限）和 Panic。

```yaml
# 策略一：忽略错误，放行请求（默认）
errorPolicy: ignore

# 策略二：返回 500 错误
errorPolicy: deny

# 策略三：返回自定义状态码和消息体
errorPolicy:
  denyWith:
    status: 403
    body: "Script execution failed"
```

**ignore（默认）**

脚本出错时，忽略错误并继续正常转发请求，就像脚本没有执行一样。这是 fail-open 策略，适合用于非关键性的增强逻辑（如注入调试头、记录上下文信息）。使用该策略时，脚本错误不会影响请求的正常处理，但会产生错误日志。

注意：`ignore` 策略仅对非预期错误生效。如果脚本主动调用 `deny()` 或 `terminate()`，该调用是脚本的正常逻辑，不受 `errorPolicy` 影响，会按照 `deny()` 和 `terminate()` 的语义执行。

**deny**

脚本出错时，网关返回 HTTP 500 并中止请求处理。这是 fail-close 策略，适合安全关键场景（如权限校验、访问控制），确保脚本出错时不会误放行请求。

**denyWith**

与 `deny` 类似，但可以自定义返回的 HTTP 状态码和响应体内容。`status` 必须在 100–599 范围内，`body` 为纯文本字符串。适合需要向客户端返回特定错误格式的场景。

生产环境中，对于安全相关的脚本（权限检查、速率标记等），建议使用 `deny` 或 `denyWith`；对于增强性脚本（添加调试头、设置上下文），可以保留 `ignore`。

## 运行时错误类型

以下错误类型由 VM 在运行时产生，触发后根据 `errorPolicy` 处理：

| 错误类型 | 触发条件 | 说明 |
|----------|----------|------|
| `TypeError` | 类型不匹配的操作（如 `"abc" - 1`） | 运算符要求的类型不满足 |
| `DivisionByZero` | 除数为零 | 整数除法除以零 |
| `IntegerOverflow` | 算术溢出 | 运算结果超出 i64 范围 |
| `StepLimitExceeded` | 执行步数超限 | 可能存在无限循环或过度计算 |
| `LoopLimitExceeded` | 循环迭代超限 | 单个循环迭代次数过多 |
| `CallLimitExceeded` | 函数调用超限 | 内置函数调用次数过多 |
| `StackOverflow` | 栈深度超限 | 表达式嵌套过深 |
| `StringTooLong` | 字符串过长 | 字符串拼接结果超过 `maxStringLen` |
| `RegexError` | 正则错误 | 正则解析或执行失败 |
| `HttpCallError` | `http.call()` 参数校验失败 | URL 协议不合法或地址被 SSRF 拦截；调用返回 `status = 0`，**不会**抛出运行时错误 |
| `ApiError` | API 调用失败 | PluginSession 接口调用异常 |

`TypeError` 是最常见的运行时错误，通常由脚本逻辑处理了可能为 `nil` 的值（如请求头不存在时对其进行字符串操作）。建议在脚本中对从外部读取的值（`req.header()`、`ctx.get()` 等）进行 `nil` 检查。

`ApiError` 发生在内置函数与网关内部接口交互失败时。这类错误通常是临时性的，在 `ignore` 策略下不会影响请求。

## Panic 隔离

VM 的 `execute_safe` 函数使用 Rust 标准库的 `std::panic::catch_unwind` 包裹整个执行过程。这意味着：

- 即使 VM 内部因为不可预期的状态触发 panic，该 panic 也不会向上传播到网关的请求处理主流程
- panic 被 `catch_unwind` 捕获后，VM 将其转化为一个执行错误，再根据当前配置的 `errorPolicy` 决定后续行为
- 网关会记录 panic 的详细信息（包括 panic 消息和脚本名称）到错误日志，便于排查

Panic 隔离是最后一道防线，在正常的脚本逻辑和运行时错误处理均无法覆盖某个边界情况时提供保护。对于经过充分测试的脚本，在正常负载下不应触发此机制。

## 正则表达式安全

DSL 的正则表达式功能在设计上防范 ReDoS（正则拒绝服务）攻击：

**编译期预编译**：`.matches()` 方法中使用的正则模式在脚本编译期就被解析和编译，编译后的结果被缓存。每次请求到来时直接使用缓存的编译结果，不会重新编译正则，消除了编译阶段的时间消耗。

**语法校验**：不合法的正则模式会在编译期报错，不会延迟到运行时才失败。这样可以在脚本加载阶段就发现正则错误，而不是在生产流量中才暴露问题。

**长度限制**：正则模式长度上限为 1,024 字节，防止超长模式占用过多内存。复杂度极高的正则模式（如包含大量反向引用或嵌套分组）在理论上仍可能造成匹配时间过长，`maxSteps` 限制可以作为额外保障。

`regex_find()` 和 `regex_replace()` 函数的模式参数同样受 1,024 字节限制约束。

## 执行阶段限制

DSL 插件可以在两个阶段运行，不同阶段的可用 API 有所不同：

| 阶段 | 可用 API | 不可用 API | 说明 |
|------|---------|-----------|------|
| `requestPlugins` | `req.*`、`ctx.*`、`deny`、`next`、`terminate`、`grpc_error` | `resp.set_status`（调用返回 `nil`，无实际效果） | 请求转发前执行 |
| `upstreamResponseFilterPlugins` | `req.*`（只读）、`resp.*`、`ctx.*`、`deny`、`next` | `grpc_error`、`terminate` | 响应头阶段执行 |

在响应阶段，`req.*` 系列函数仍然可以调用，但修改操作（如 `req.set_header()`）不会对已经转发出去的请求产生影响，仅供读取请求信息使用。

`grpc_error()` 只在请求阶段有效，因为 gRPC 状态码通过 HTTP/2 trailers 传递，而 trailers 只能在响应体发送之前设置。在响应阶段调用 `grpc_error()` 会降级为 `terminate()` 行为，并产生一条警告日志。

## 函数级别限制汇总

部分内置函数除了受全局资源限制约束外，还有自身的参数或结果限制：

| 函数 | 限制 | 说明 |
|------|------|------|
| `json_get` | 路径最多 32 段；JSON 大小受 `maxStringLen` 限制 | 防止深层嵌套路径访问 |
| `time_format` | 格式字符串最大 256 字符 | 防止格式字符串过长导致的资源消耗 |
| `regex_find` / `regex_replace` | 模式最大 1,024 字节 | 防止 ReDoS |
| `req.header_names` / `resp.header_names` | 最多返回 256 个头名称 | 防止大量请求头导致的内存问题 |
| `resp.set_status` | 状态码范围 100–599 | 超出范围时返回 `ApiError` |
| `range` | 最多生成 1,000 个元素 | 防止大列表占用过多内存 |
| `http.call` | 超时上限 `httpMaxTimeoutMs`（默认 5,000 ms）；响应体上限 `httpMaxResponseBodyBytes`（默认 1 MiB）；仅支持 `http`/`https`；`httpBlockPrivateIps: true` 时拦截私有 IP | 防止网关资源耗尽和 SSRF 攻击 |

`json_get` 的路径段限制（32 段）针对的是路径表达式中的层级数量，例如 `"a.b.c.d"` 是 4 段。超过 32 段的路径在实际业务中极为罕见，该限制不会对正常使用造成影响。

`req.header_names()` 和 `resp.header_names()` 返回一个字符串列表。当实际头数量超过 256 时，只返回前 256 个，不产生错误。如果需要遍历所有头，应当结合具体的头名称使用 `req.header()` 直接访问。
