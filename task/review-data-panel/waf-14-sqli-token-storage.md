# SQLi folding and finalized token storage

Status: deferred representation/performance decision for user review. No runtime change.
Source baseline: `fc2e39648`.

## Evidence

Gateway WAF execution reaches `injection::detect_sqli` through the compiled
DetectSqli operand in `edgion-waf/src/seclang/transaction.rs`, after detector
input/work admission. The wrapper constructs SqliState over borrowed input and
returns a fixed-size fingerprint; it does not call fingerprint_string.

SqliState owns two SmallVec<[Token; 8]> fields: token_vec is the folding workspace,
and public tokens is the finalized projection used by fingerprint generation and
false-positive whitelist checks. Token contains scalar metadata and a 32-byte
array, so its clones do not duplicate heap-owned strings or buffers.

Each fold clears and resizes token_vec to MAX_TOKENS + 3 (eight slots). The normal
final projection copies up to five entries, filtering None tokens, then may append
the last comment if space remains. The degenerate-brace early return copies a
different range. Fingerprint generation can replace the finalized list with one
Evil token. The whitelist reads token bytes, lengths and quote metadata as well as
parser statistics. Conditional dialect/quote reparsing resets state and repeats
folding in up to five contexts. These are distinct representations, not merely
two interchangeable copies of one slice.

## Decision alternatives

- Retain the current bounded, inline storage if measured gains are negligible.
- Replace only the fixed-length scratch container with an array. This may simplify
  container bookkeeping but does not remove the final projection or token copies.
- Use one storage owner with explicit finalization and a finalized length/view.
  This could avoid projection copies, but must reproduce filtering, comment
  insertion, early returns and Evil normalization before every consumer.

No alternative is selected. Replacing Clone with Copy or moving an array-backed
token is not, by itself, evidence that machine-level copies disappear. Measure
optimized code and end-to-end SecLang cost, including ordinary short inputs and
reparse-heavy/adversarial inputs, before accepting added representation complexity.
No allocation-count, stack-frame, RSS or throughput improvement is established.

## Acceptance before implementation

Preserve the exact behavior pinned in [INJECTION.md](../../edgion-waf/INJECTION.md):
verdicts, fingerprints, folded token contents and return counts, byte positions,
truncation, quote metadata, variable counts, statistics, reset behavior and all
early returns. Audit the folding-fixture consumer of public tokens and all callers
before changing that representation; update callers directly without compatibility
shims. Do not infer equivalence from matching verdicts alone.

Compare the current Rust implementation and the exact pinned local Go reference
using existing fixtures and generated byte inputs. Exercise empty/comment-only
inputs, all quote/dialect contexts, five-token lookahead, cascading folds, trailing
comments, degenerate braces, Evil tokens, high bytes and whitelist boundaries.
Keep the 4 MiB detector input cap, cumulative work charges, local work guards,
negation, chain atomicity and fingerprint capture unchanged. Introduce no request
cache, new observability, unsafe storage or unbounded retention. Freeze an exact
cross-crate edit allow-list and obtain independent IMPL plan/final review first.
